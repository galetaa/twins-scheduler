Abstract. Fault-injection frameworks for Byzantine fault-tolerant protocols expose different
amounts of control over message delivery: some choose a partition or directed communication graph for an entire view, while others distinguish message phases, individual instances,
or replay. A richer scheduler trivially generates more executions, but it is unclear when that
additional authority changes the set of safety-relevant observations rather than merely producing redundant traces.
We study closure from phase-specific delivery to one type-uniform directed endpoint graph
for finite certificate-driven locking schemas. First, we give a relational sufficient condition
under which closure-added messages preserve an unsafe observation. We then identify its
locking boundary: repair evidence added by type erasure can disable the unique honest participant shared by two conflicting quorums. For every f ≥ 1, with n = 3f + 1 and q = 2f + 1,
we construct an explicit schema in which phase-specific delivery forms both conflicting certificates, whereas both directed-edge choices remain safe. We derive an exact seven-premise
characterization of this construction and separately prove that exact replay is observationally erasable only under a projection-congruence condition: equal protocol-relevant projections, including processed stable keys, must remain equal after every future event; a marked
duplicate must be a projected stutter and produce no protocol-relevant output.
The obligations are independently re-encoded as Z3 CHC/SMT queries, cross-checked with exact Go big-integer arithmetic, and reproduced in two bounded locking kernels plus a fuller
two-round Go event loop and an independent Python mirror. The work establishes an explicit safety-observation boundary; it does not claim universal incompleteness of graphbased schedulers, a production-client vulnerability, or a liveness result.

1. Introduction
Byzantine fault-tolerant (BFT) consensus protocols are tested under adversarial message schedules because the same protocol code can exhibit materially different behavior when messages are dropped, delayed, reordered, duplicated, or selectively delivered. Testing frameworks expose this adversarial authority through a scheduler grammar: a language for saying which communication actions are permitted
in each execution. Twins uses replicas with a shared identity and round-indexed communication partitions to realize equivocation-like scenarios without a hand-written malicious implementation (Bano et
al. 2022). Communication-closure testing reduces asynchronous executions to controlled round-based
schedules for a suitable class of consensus implementations (Drăgoi et al. 2020). ByzzFuzz adds randomized message mutations and partitions (Winter et al. 2023), Netrix offers programmer-guided filters and
monitors (Drăgoi, Nagendra, and Srivas 2024), and ByzzBench provides common infrastructure for comparing testing algorithms (Neto and Ozkan 2025).
These systems differ in more than search strategy. A partition schedule makes one symmetric connectivity choice for a view. A directed schedule distinguishes sender–receiver orientation. A phase-specific
schedule can separate two messages that share the same endpoint pair but serve different protocol roles.
A per-instance scheduler can additionally distinguish individual messages and delivery order. A replaycapable scheduler may deliver the same logical signed action more than once.
The corresponding raw execution languages are ordered almost by definition: every partition schedule
can be represented by a directed graph, every phase-specific graph can be represented by per-instance
decisions, and so on. That inclusion is not the scientific question. Two grammars may generate different
internal traces while exposing exactly the same agreement violations. Conversely, a coarser grammar
may be forced to deliver an additional valid message whose protocol effect repairs the unsafe execution.
We therefore study a property-preserving closure problem:
Central question. When does erasing message-phase distinctions to one type-uniform directed endpoint graph preserve every finite agreement-violation observation, and when can

the messages added by that closure destroy the witness?
The mechanism is non-monotone locking repair. Suppose closure inserts only transitions that are increasing in a preorder under which the unsafe set is upward closed. Then unsafety survives. A repair or
terminal certificate in a locking protocol need not satisfy that premise: receiving it may strengthen a lock,
cause an irreversible decision, or otherwise remove a validator from a future conflicting quorum. If that
validator is the unique honest pivot shared by two quorums, closure can change an unsafe trace into a
safe one even though it only adds deliveries.
This distinction matters for the interpretation of fault-injection results. The richer scheduler is not
automatically better merely because it generates more traces, and the coarser scheduler is not automatically safety-complete merely because it represents partitions or arbitrary directed graphs. What matters
is whether a closure between grammars preserves the selected safety observation for the protocol class
under study.
1.1 Contributions
This paper makes three narrow contributions.
1. Relational closure lifting. We state and prove a sufficient condition under which inserting the messages required by a coarser scheduler preserves a finite unsafe observation. The theorem exposes the
exact local obligations: inserted actions must be increasing under a preorder, retained actions must
forward-simulate it, and the unsafe set must be upward closed.
2. Parametric quorum-pivot separation and exact premise boundary. For every integer f ≥ 1, with
n = 3f + 1 and quorum threshold q = 2f + 1, we construct a two-branch certificate-driven schema
in which a phase-specific scheduler can form two conflicting certificates, while both choices of the
corresponding type-uniform directed edge remain safe. The construction isolates a unique honest
quorum pivot and two differently labelled messages, enabling evidence E and later repair evidence R,
on the same edge. For the supplied seven-flag operational abstraction, strict separation holds exactly
when
S2 ∧ D ∧ T ∧ Ed ∧ X ∧ (S1 ∨ Rq ).
3. Replay boundary and executable assurance. We prove exact replay erasure under a stable-key projection that is congruent with every future transition, together with projected-stutter and silent-output
conditions for marked duplicates. We include the hidden-state trace X,X,Y showing why immediate
projected stutter alone is insufficient. The scheduler separation is validated in two exact locking kernels and a fuller two-round event loop; the post-audit obligations are also checked by an independent
script and an executed project-local proof-certificate kernel with four rejected damaged controls.
The paper is deliberately not framed as a new testing domain-specific language. Partition scenarios,
message filters, delay, reordering, replay, mutation-based BFT testing, and benchmark infrastructure are
prior art (Bano et al. 2022; Winter et al. 2023; Drăgoi, Nagendra, and Srivas 2024; Neto and Ozkan 2025).
The contribution is the effect of one closure transformation on the unsafe-observation language.
1.2 Scope and nonclaims
The results concern finite agreement observations of explicit certificate-driven schemas. They are not
a universal incompleteness theorem for partition or directed schedulers. They do not establish a vulnerability in HotStuff, Tendermint, CometBFT, or any deployed client. They do not address liveness or
unbounded partial synchrony, and they do not estimate the prevalence or discovery probability of real
bugs. The production specifications and source snapshots in the artifact are used to discipline terminology and implementation assumptions, not as evidence of a production defect.

different replay keys while competing for the same contribution key.
The schema abstracts signatures by assuming that a scheduler cannot forge a message attributed to a
correct identity and that certificate signer sets are explicit. The central separation does not depend on a
particular signature scheme. Byzantine identities may contribute to conflicting certificates, as usual in a
Byzantine fault model (Lamport, Shostak, and Pease 1982).
A lock is persistent protocol state restricting future support. The schema does not require one universal
lock rule; the separation only requires that a later repair or terminal message can remove one honest
validator from a conflicting branch. This may occur by strengthening a lock, finalizing a value, or setting
another state predicate that blocks the relevant contribution.
2.2 Safety observation
Let H ⊆ N be the correct validators. For agreement, the terminal observation is
Os (s) = (decisioni )i∈H .
A state is unsafe when two correct identities have distinct non-null decisions:
Unsafe(s) ≡ ∃i, j ∈ H. decisioni ̸= ⊥ ∧ decisionj ̸= ⊥ ∧ decisioni ̸= decisionj .
The observation intentionally excludes internal logs, counters, and transient scheduling state unless
they change a protocol-visible transition. This prevents a raw trace difference from being mistaken for a
safety separation.

2.4 Execution and observation languages
For a protocol P , scheduler grammar G, and bounded domain B, let LG (P, B) be the set of admissible

and controlled message production. Define

schemas and proves the distinction independent of finite enumeration.
2.5 Closure operators
Three closures are relevant.
Phase/type erasure Ctype . Starting from a GT schedule, retain every directed endpoint edge used in
a view and admit every controlled phase on that edge. The closure erases phase selectivity but does not
add reverse edges.
Terminal-time erasure Ctime . Starting from a GD1 schedule, deliver admitted terminal evidence immediately rather than in the next view.
Replay erasure Cdup . Starting from a GR trace, retain the first delivery of each replay key and delete
later identical deliveries. Distinct signed actions and equivocations remain.
The rest of the paper characterizes when these closures preserve the selected finite safety observation.

3. Relational closure lifting
3.1 Merged traces
Let τ = a1 . . . ak be an original finite execution. A closure trace C(τ ) is a merged sequence that retains
every original action in the same relative order and inserts additional actions required by the coarser
grammar. For phase erasure, an inserted action is typically the delivery of a different phase label on an
endpoint edge that the original trace used for some other label.
Let S be the protocol-relevant state space and R ⊆ S × S a preorder. Intuitively, R(s, t) means that t
contains at least the safety-relevant progress represented by s. This interpretation is deliberately conditional: a protocol instance must supply a meaningful relation, and a repair transition may make such a
relation impossible.
3.2 Sufficient conditions
We use four obligations.
1. Initial relation. The original and closure executions start in related states.
2. Increasing insertion. For every closure-added action b, if b maps t to t′ , then R(t, t′ ).
3. Forward simulation of retained actions. If R(s, t) and an original action a maps s to s′ , then the
corresponding retained action maps t to some t′ such that R(s′ , t′ ).
4. Upward-closed unsafety. If Unsafe(s) and R(s, t), then Unsafe(t).
Theorem 1 (Relational closure lifting; T2)
Let τ be a finite execution ending in an unsafe state. Let C(τ ) preserve the order of the original actions and
insert only closure-added actions. If a preorder R satisfies the four obligations above, then the terminal
state of C(τ ) is unsafe.
Proof
Traverse the merged trace while relating the state after the original actions consumed so far to the state
after the corresponding merged prefix. Initially the relation holds by premise 1. When the next merged
action is inserted, the original side does not move; increasing insertion and transitivity preserve the relation. When the next merged action is retained from τ , both sides advance and forward simulation
preserves the relation. Induction over the finite merged trace therefore relates the unsafe terminal state
of τ to the terminal state of C(τ ). Upward closure of unsafety yields the result. □
If R additionally preserves the complete selected observation in both directions, the same argument
yields observation equality rather than only preservation of unsafety. The weaker theorem is more useful
here because the closure may legitimately change non-safety state.
3.3 Why the theorem is not tautological
The theorem does not assume that every added message is harmless. That is precisely the per-instance
obligation. An inserted message may violate increasingness for any preorder that preserves future quorum participation. For example, a terminal certificate delivered to a pivot may cause an irreversible
decision and suppress the pivot’s later vote for a conflicting value. The closure state then contains more
received evidence but fewer available future actions. A naïve subset order on received messages is therefore insufficient.
The parametric construction in the next section is a failed-premise boundary of Theorem 1. It demonstrates that the missing monotonicity is not merely a formal technicality: it determines whether an
agreement-violation witness exists.

For GT , E enables p before C0 , so the first branch reaches q. Because R is withheld, p remains eligible at
C1 , the second branch also reaches q, and the two correct decisions conflict.
For GD there are only two executions:
• edge off (b = 0): neither E nor R is delivered. The first branch has only 2f = q − 1, so h0 never decides
0;
• edge on (b = 1): both E and R are delivered in the fixed order. The first branch may reach quorum, but
R is processed before C1 and disables p. The second branch remains at 2f = q − 1, so h1 never decides 1.

Proof

6. Replay erasure and its boundary
Phase erasure concerns messages with different roles. Replay concerns another dimension: repeated
delivery of one exact logical action. Immediate invisibility of a duplicate is not sufficient for erasure
because hidden state can affect later behavior.
6.1 Relevant projection and future congruence
Let S be the complete state and let
π : S → Srel
project to all state relevant to the selected safety observation. The projection explicitly includes the
processed stable replay keys as well as protocol state used by future handlers. Let δ(s, m) be the next state
and let out(s, m) be protocol-relevant output.

1. projection congruence

for every future event m;
2. marked-duplicate stutter: if an occurrence m has already been classified by its stable key as a duplicate, then

Theorem 4 (Replay erasure; T1)
For every finite marked trace τ and initial state s0 , deleting all occurrences marked as exact stable-key
duplicates preserves the final relevant projection and every state-based observation that factors through
it.
Proof
Use the stronger induction invariant that the erased execution may begin in state s and the full execution
in state t with π(s) = π(t). For a retained event, projection congruence establishes the invariant for the two
successor states. For a marked duplicate, the erased execution stays at s, while the full execution moves
from t to δ(t, m); duplicate stutter and transitivity of equality re-establish the same projected relation.
Applying the induction hypothesis to the remaining suffix proves equality of terminal projections. Silent
output prevents an erased duplicate from changing the relevant output trace. □
6.2 Why immediate stutter alone fails
Consider complete state (r, h) with relevant projection π(r, h) = r. Event X toggles hidden bit h without
immediately changing r; event Y copies h into r. Starting at (0, 1),

6.3 Non-idempotent quorum boundary
Replay erasure also fails when quorum code counts message instances rather than unique logical contribution keys. For threshold three, B,H1,H1 contains only two validator contributions but three deliveries;
a defective instance counter may reach quorum only under replay. This is a model boundary, not an
allegation about a production client. Replay may likewise remain observable through timers, resource
usage, callbacks, or liveness even when state-based safety is preserved.

7. Executable validation
The symbolic separation is the central contribution. Executable models serve three narrower purposes:
they test whether the mechanism survives a less algebraic event semantics, expose implementation confounders, and provide replayable witnesses. They do not turn a bounded experiment into a universal
protocol theorem.
7.1 Exact locking kernels
Two dependency-free finite-state kernels instantiate certificate-driven locking behavior with n = 4, f = 1,
and quorum q = 3. Both use one Byzantine logical identity represented by two physical branches, three
correct identities, binary conflicting values, two rounds, and an independent agreement oracle.

The first kernel uses generic proposal, vote, intermediate-certificate, precommit, and commit evidence.
The second uses Tendermint-style vocabulary: proposal, prevote, POLKA, persistent lock and valid-round
state, precommit, and commit. The pinned CometBFT specification and source snapshot are used only to
check that these phase and lock concepts are natural engineering abstractions (CometBFT Project 2026).
The kernels contain controlled obligation violations, not discovered production defects.
Across both kernels, the correct baseline remains safe under all tested scheduler grammars. Controlled
mutations show distinct expressiveness boundaries:
• omitting a lock update or using a wrong justification guard is hidden from the type-uniform directed
grammar but exposed by phase-specific delivery;
• one-view delay of terminal evidence detects some lock-related mutations but not a defect requiring
discrimination between two intermediate quorum-forming phases;
• a duplicate-counting mutation requires replay;
• a receiver-validation omission is a positive control detectable already under a partition grammar.
These outcomes prevent the checker from being interpreted as a machine that mechanically declares
richer grammars necessary for every defect.
7.2 Fuller two-round event loop
The stronger validation route is an explicit event loop with dynamically generated messages and phases
PROPOSAL -> PREVOTE -> POLKA -> PRECOMMIT -> COMMIT.
The logical participants are leader B and correct replicas H1, P , and H3. Round 0 proposes value 0 to
H1 and pivot P ; round 1 proposes value 1 to P and H3. Votes are indexed by unique contribution keys, a
POLKA forms after three unique prevotes, and COMMIT evidence forms after three unique precommits.
Locks persist across rounds, decisions are irreversible, and the agreement oracle is independent of the
scheduler implementation.
The only controlled mutation, MISSING_LOCK_UPDATE, suppresses the persistent lock assignment when
a correct replica accepts a POLKA. No other transition changes. Only the round-0 edge B → P is controlled:
• GT delivers proposal and POLKA but withholds COMMIT;
• GD with the edge off withholds every controlled phase;
• GD with the edge on admits every controlled phase.

7.4 Closure counterfactuals
For each decisive witness, the artifact constructs the nearest closure counterfactual.
• Phase erasure: allowing every phase on the used endpoint edge adds terminal repair evidence and
removes the conflicting terminal observation.
• Terminal-time erasure: delivering the delayed terminal message immediately removes the lockrelated witness, but does not simulate cases that require discriminating two intermediate phases.
• Replay erasure: deduplicating exact signed actions removes the false quorum of the instance-counting
mutation.
The counterfactuals link the language difference to a named mechanism rather than merely reporting
that two search procedures found different traces.

8.3 Evidence separation
The paper distinguishes three evidence levels.
• Theorem evidence: paper proofs, SMT/CHC obligations, and exact symbolic arithmetic.
• Bounded semantic evidence: exhaustive kernels, all 128 premise assignments, and event-loop cases.
• Engineering correspondence evidence: pinned source/specification fragments and a Go fixture for

9. Related work and novelty boundary
9.1 Clone and partition testing
Twins represents selected Byzantine behaviors through correct-code copies sharing one identity and controls their communication by rounds (Bano et al. 2022). It demonstrates leader equivocation, double
voting, and state-loss scenarios and provides an important practical source of partition-style testing. The
present work grew out of a rejected attempt to establish a finite-clone completeness result. That question
collapsed under a more general state-equivocation model and a standard chain-cover interpretation of
persistent clone histories. The contribution here is different: it fixes the process-side behavior and asks
whether scheduler phase erasure preserves agreement-violating observations.
The distinction is important. Theorem 2 does not say that Twins cannot reproduce a particular production attack or that clone-based testing is generally incomplete. It identifies one language transformation—
from phase-labelled directed delivery to one type-uniform directed graph—and gives an explicit schema
where that transformation removes a safety witness.
9.2 Communication closure and message adversaries
Communication closure provides a principled way to reduce certain asynchronous consensus executions
to more canonical schedules for testing (Drăgoi et al. 2020). Heard-Of and message-adversary models
represent round communication by receive sets or directed graphs (Charron-Bost and Schiper 2009; Winkler, Schmid, and Moses 2020). These works are the closest conceptual prior art because they show that
scheduler normalization can preserve properties under structural conditions.
Our result is narrower in protocol scope but different in the closure dimension. We do not characterize
consensus solvability under graph languages, nor do we claim a general reduction from asynchrony. We
examine whether erasing message roles on one endpoint edge preserves a finite agreement observation.
The relational theorem gives a generic sufficient condition, while the quorum-pivot family exposes a nonmonotone repair mechanism that violates it.
Recent work also formalizes broad fault-injector libraries, including loss, duplication, delay, tampering,
equivocation, and partitions, for statistical performance analysis in Maude (Zhou et al. 2026). That framework further confirms that rich fault actions and executable injector composition are engineering/formal
prior art. Its main target is quantitative performance prediction; it does not establish the phase-erasure

Anonymous post-audit submission draft

13/16

safety-observation theorem or the quorum-pivot boundary studied here.
9.3 Richer testing languages and mutation systems
Randomized BFT testing constructs message mutations and network partitions to search for protocol bugs
(Winter et al. 2023). Netrix provides filters, monitors, reproducible scenarios, and programmer-guided
exploration over distributed protocol implementations (Drăgoi, Nagendra, and Srivas 2024). These systems show that message-level drop, delay, ordering, and replay are not novel operations. Their purpose
is to discover and reproduce bugs efficiently.
Our question is orthogonal: under what conditions does removing one kind of scheduler distinction
leave the safety-observation language unchanged? The result does not propose a replacement testing
framework. A tool builder may use the characterization to decide whether a phase-specific control is
semantically necessary for a protocol/mutation class, but that implication is secondary.
9.4 Benchmark and implementation infrastructure
ByzzBench standardizes protocol implementations and controls concurrency, network, and process faults
so testing algorithms can be compared (Neto and Ozkan 2025). Counting discovered bugs, comparing
exploration cost, or constructing a benchmark corpus is outside our contribution. The executable kernels
in this paper are theorem witnesses and regression artifacts, not a claim of benchmark superiority.
The pinned CometBFT and relab/hotstuff sources (CometBFT Project 2026; relab 2026) threaten practical novelty—for example, they document phase structures, lock updates, duplicate-vote handling, and
partition admission. They do not constitute proof that the abstract separation applies to a complete client,
and the paper makes no such claim.
9.5 Novelty statement
The nearest works establish partition/clone testing, communication-closure reductions, directed messageadversary models, message-level mutation/filtering, fault-injector composition, and benchmark infrastructure. The search was refreshed through 20 August 2026 and additionally included PERF and ByzTwinRange. In the examined sources, we did not find a result that simultaneously:
1. defines closure from per-phase delivery to one type-uniform directed endpoint graph;
2. studies preservation of finite agreement-violation observations under that closure;
3. identifies closure-added repair evidence disabling a unique honest quorum pivot; and
4. pairs the separation with a replay-erasure theorem using explicit projection congruence and the
hidden-state counterexample.
This is a bounded search statement, not proof of absolute novelty. The claim must be refreshed immediately before any submission, including refinement/conformance literature, dissertations, specifications,
and engineering discussions that may not use BFT-testing terminology.

10. Validity, limitations, and responsible use
10.1 Internal validity
A shared implementation mistake could produce a spurious language difference. Controls include independent Go and Python event loops, exact SMT encodings, a separate certificate checker, exact big-integer
arithmetic, exhaustive evaluation of all seven-premise assignments, and FIFO/LIFO/random queue-order
variants. The remaining limitation is that all executable models follow a common written abstraction and
can share a specification error.
The correct baseline is safe under all canonical grammars, and a positive-control validation defect is
visible even under a partition grammar. These facts reduce, but do not eliminate, the risk that the checker
is biased toward finding a separation whenever more control is available.
10.2 Construct validity
Scheduler expressiveness is defined by exact unsafe-observation languages, not by schedule counts, code
coverage, or bug yield. The selected observation is agreement among correct decisions. A different property may induce a different grammar ordering. In particular, a replay that is invisible to state-based safety
may still matter for resource exhaustion, timing, callbacks, or liveness.

Anonymous post-audit submission draft

14/16

The phase-erasure closure is also specific: it couples different controlled labels on the same directed
endpoint edge. Other partition implementations may admit selected message types outside partitions, use
asymmetric rules, or maintain pending queues with different semantics. Such systems require a separate
conformance map before the theorem language is applied.
10.3 External validity
The central theorem is an explicit schema family with unweighted 3f + 1 quorums. It does not cover
weighted stake, changing validator sets, chained multi-height commits, optimistic responsiveness, pacemakers, disk persistence, or recovery. Two bounded locking abstractions and a fuller event loop show
that the mechanism is not confined to a one-line terminal formula, but they do not establish universal
transfer to HotStuff or Tendermint.
A natural protocol instantiation must show, rather than assume, that enabling and repair evidence
share one scheduler edge, that repair can disable the relevant pivot before the second certificate opportunity, and that no alternative honest contributor replaces that pivot. The current mapping is therefore
conditional.
10.4 Conclusion validity
The decisive results are logical language differences and exact finite outcomes. No p-values, confidence
intervals, or bug-discovery probabilities are reported. Counts such as 1,548 event-order runs are robustness checks, not samples from a population of production executions. The universal claim in Theorem 2
is only over the integer parameter of the supplied schema and is supported by algebraic proof obligations.
10.5 Proof assurance
The SMT, independent script, project-local proof-certificate kernel, arithmetic checks, and dual implementations substantially reduce implementation error. The project-local kernel was executed and includes
negative controls, but it is not a substitute for an externally maintained prover. The Lean and Coq sources
are included but unbuilt and are not counted as mature-prover evidence. This residual assurance limitation is explicit rather than hidden behind a generic claim that “formal verification was performed.”
10.6 Responsible security interpretation
All adversarial schedules and mutations execute locally. The artifact does not contact a mainnet, send
traffic to public validators, move assets, obtain private keys, or attempt denial of service. No exploit
against a live implementation is published. A future unexpected implementation-level finding should be
privately reproduced, minimized, and disclosed to maintainers before public release of sensitive details.
10.7 Explicit nonclaims
The paper does not claim:
1. a production vulnerability in CometBFT, HotStuff, Tendermint, or another client;
2. universal incompleteness of partition or directed scheduler grammars;
3. universal minimality of phase-specific scheduling;
4. a liveness theorem or unbounded partial-synchrony completeness result;
5. an estimate of real-bug prevalence or discovery probability;
6. production-client conformance of the isolated event loop; or
7. absolute novelty.

12. Conclusion
A richer scheduler trivially generates more traces, but the relevant question for consensus testing is
whether it generates new safety observations. We showed that phase/type erasure is not automatically
property preserving. A relational closure theorem identifies sufficient monotonicity conditions under
which inserted messages preserve unsafety. Certificate-driven locking can violate those conditions:
closure-added repair evidence may remove the unique honest pivot shared by two conflicting quorums.
For every f ≥ 1, the quorum-pivot family separates phase-specific delivery from a type-uniform directed endpoint graph with n = 3f + 1 and q = 2f + 1. The exact seven-premise boundary identifies
when the mechanism is active inside the supplied operational abstraction. Stable-key duplicate stutter
together with projection congruence gives the complementary condition under which exact replay adds
no state-based safety-observation power.
The result provides a disciplined vocabulary for scheduler expressiveness. It separates raw trace inclusion, API richness, and bug yield from a formal property-preservation claim. Its appropriate use is
narrow: prove the closure obligations for a protocol class, or produce a separation witness and state the
missing premise. Extending the claim to a deployed protocol requires an explicit refinement argument
and independent proof review.
